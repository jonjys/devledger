Trust

Don't trust us. Check.

A tool that holds your keys should not ask for faith. Everything below can be checked in a few minutes, with tools you already have, without taking our word for anything.

How to check Read the source

Start without keys

You don't have to put a single secret in to get something out of DevLedger. Add which email owns which account, which project uses which database and what each plan costs. The map, Costs and Needs attention all work on names alone. Add keys later, when you have checked the rest, and keep production keys in the desktop app.

Verify it yourself

1. Watch the network

Open the web app, then your browser's developer tools (F12, or right-click → Inspect) and the Network tab. Filter on Fetch/XHR. Create a vault, add projects and keys, lock and unlock. The list stays empty. The one exception is pressing a button under Assistant, which sends the outline you can read first under “What is sent?”.

2. The counter in the app

The pill in the web app's top bar counts every request the page makes that could carry data out: fetch, XHR and beacons. It is wired in before any other code loads, and WebSockets are refused outright. Click it to see each request. It should agree with the Network tab.

3. The walls around the page

In the Network tab, click the page itself and look at its response headers. The Content-Security-Policy says connect-src 'self' https://api.github.com: the browser itself blocks this page from sending anything to any other address, even if a line of code tried.

4. Where the encryption happens

The web app's vault is one short file: PBKDF2 (600,000 rounds) into an AES-256-GCM key the browser will not let script read, a fresh IV on every save. In the developer tools under Application → Local Storage you can see what is stored: ciphertext only.

5. The downloads

Every installer is built by GitHub Actions from the public source, with public build logs, and published with its SHA-256 checksum. The download section shows how to compare it with the file you got.

6. Build it yourself

git clone https://github.com/jonjys/devledger, then npm ci and npm run build:web in apps/desktop builds this exact website, or npm run tauri build the desktop app. Nothing in it needs an account or a key of ours.

You can always leave

The web app's Backup button downloads your vault as a file, still encrypted with your passphrase. Restore backup opens it in another browser or on another computer. There is no lock-in and no copy with us, which also means no recovery if you lose both the passphrase and the file.

Privacy

What we never get

Your vault, your keys, your passphrase and your list of accounts. There is no DevLedger account, no database of users and nothing to sync to. The site sets no cookies and runs no analytics or tracking.

What hosting sees

The site is served by Vercel, which, like any web host, sees the requests for the pages and files (address, time, which file) and keeps its own server logs under its own terms. The home page asks GitHub's API, from your browser, which release is the latest.

The AI assistant

Only when you press one of its buttons. What it sends is an outline of names and connections, with no key values and with every email address replaced by a placeholder, and you can read it before it goes. On the website it passes through our function to Anthropic, which answers it; our function does not store it. In the desktop app it goes straight to Anthropic with your own key.

The desktop app

Talks to the network only when you press Connect or Refresh for a provider, or ask the assistant. No updates checks, no crash reports, no telemetry. The threat model says exactly what it protects against and what it does not.

Found a problem?

Report a security problem privately through GitHub's security advisories (also listed in security.txt). Anything else goes in the issue tracker. DevLedger is early software and has not had an independent audit yet; we would rather hear about a flaw from you than read about it.
